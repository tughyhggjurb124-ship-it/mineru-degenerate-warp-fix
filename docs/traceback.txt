Real evidence from a MinerU 4.0.12 install (site-packages paths shortened, job id and
file name redacted). The parse server runs with `--tier basic` and writes this to

    <MINERU_HOME>/logs/doclib.parse-server.stderr.log

The error envelope a client receives instead of a result
--------------------------------------------------------

    {
      "error": {
        "type": "engine_error",
        "code": "parse_failed",
        "message": "Unsupported warp settings",
        "param": null
      }
    }

No output file is written, so the whole page range has to be re-parsed.

Reproduction
------------

    # with the PDF and the same page range
    mineru parse source.pdf --tier basic --pages 49-55 --wait 900 --json -o out.md --force

    # -> the engine_error envelope above, exit code 1, no out.md

After the patch, the same command finishes and writes `out.md` with the expected
`<!-- page N of TOTAL -->` markers. `repro/reproduce.py` shows the same failure at
function level, without needing a PDF or downloaded models.
